# Фронтенд — скоринг закупок (роль 4)

React + Vite + TypeScript, React Router, TanStack Query, Tailwind — как в `CLAUDE.md`.
Экраны и тексты — по разделу «Интерфейс» в `docs/analytics.md`.

## Запуск для разработки

Нужен Node.js 20+ (https://nodejs.org, версия LTS).

```bash
cd frontend
npm install        # один раз, 1–2 минуты
npm run dev        # http://localhost:5173
```

> **Windows, PowerShell пишет «выполнение сценариев отключено»?** Выполните один раз
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` или переключите терминал VS Code на Command Prompt.

По умолчанию включён **демо-режим**: бэкенд не нужен, данные тестовые. Подойдёт любая почта и пароль —
сразу будут готовые параметры и 11 закупок с разными оценками. `new@example.com` — пустой аккаунт,
чтобы пройти путь с нуля: Параметры → «Составить правила» → Загрузка → «Попробовать на примере» → Результаты.

### С настоящим бэкендом

Создайте файл `frontend/.env` со строкой `VITE_USE_MOCK=false`, запустите бэкенд на `:8000`, перезапустите `npm run dev`.
Запросы `/api/...` vite перешлёт на бэкенд. Другой адрес: `BACKEND_URL=http://host:port npm run dev`.

В `docker-compose up --build` фронт собирается с настоящим API и открывается на http://localhost:3000.

## Команды

```bash
npm run dev           # разработка
npm run build         # проверка типов (tsc) + сборка в dist/
npm run lint          # ESLint
npm run format        # Prettier: привести форматирование к общему виду
npm run format:check  # Prettier: только проверить (для PR)
npm test              # Vitest: форматы сумм/дат и проверки правил
```

Перед PR: `npm run lint && npm run format:check && npm test && npm run build`.

## Где что лежит

```
src/
  api/
    types.ts        типы данных API (сверить с OpenAPI тимлида)
    index.ts        все адреса API; переключатель демо-режима
    client.ts       fetch с cookie и единым форматом ошибок
    mock.ts         демо-«сервер» (только для разработки без бэкенда)
    mockData.ts     демо-закупки, заказчики, профиль «IT-компания из Томска»
  lib/
    catalog.ts      каталог полей правил, подписи значений, тексты ошибок, субъекты РФ
    rules.ts        формулировка правила человеческим языком, проверки при сохранении
    format.ts       суммы «4 200 000 ₽» / «4,2 млн ₽», даты ДД.ММ.ГГГГ
    hooks.ts        запросы TanStack Query: пользователь, профиль, опрос задач
  components/       Layout (шапка, вкладки, подвал с картой сайта), Logo (красная кедровая шишка), Breadcrumbs, Ticket, RuleCard, ValueEditor, ui
  pages/            LoginPage, WelcomePage (стартовая), ProfilePage, UploadPage, ResultsPage, ProcurementPage, HistoryPage
```

Новое поле в каталоге роли 3 → одна запись в `FIELDS` (`src/lib/catalog.ts`). Остальное подхватится само.

## Что сделано по ТЗ и плану

| Пункт | Где |
| --- | --- |
| Вход, регистрация, выход, имя в шапке; без входа — только страница входа | `LoginPage`, `Layout`, `App` |
| После входа — стартовая страница: три шага и кнопка «Начать» (нет профиля → Параметры) / «Далее» (→ Загрузка или Результаты) | `WelcomePage` |
| Текст → «Разобрать» → правила по трём группам; блок «Не удалось разобрать» | `ProfilePage` |
| Правило: формулировка, стоп-фактор/критерий, важность низкая/средняя/высокая, вкл/выкл, значение по типу поля | `RuleCard`, `ValueEditor` |
| Добавление правила из каталога человеческими названиями | `ProfilePage` |
| Веса групп (в процентах) и пороги; «Сохранить» и «Сохранить и пересчитать» | `ProfilePage` |
| Без LLM-ключа «Разобрать» скрыта | `ProfilePage` (`features.llm`) |
| Drag-and-drop, форматы и лимиты, «Загрузить пример», прогресс N из M, ошибки по файлам, ручной ИНН | `UploadPage` |
| «Показать результаты» активна при частичной готовности | `UploadPage` |
| Таблица, сортировка по любому столбцу (по умолчанию — оценка ↓), фильтры, счётчики, экспорт CSV/JSON, пустое состояние | `ResultsPage` |
| Карточка: оценка, «оценка неполная», стоп-факторы первыми, три группы с правилами и вкладом, «нет данных», обоснование с подсветкой правила, блоки «Заказчик» и «Закупка», «Открыть в ЕИС» | `ProcurementPage` |
| Цвет рекомендации всегда со словом; суммы и даты в нужном формате; вёрстка от 375 px | везде |

Фронтенд оценку не считает: баллы, рекомендацию и обоснование присылает бэкенд (правило 1 в CLAUDE.md).
Маленький расчёт в `mock.ts` нужен только для того, чтобы демо-режим реагировал на правку правил.

## Дизайн «сортировочный стол»

- «Результаты» — итог одной фразой и таблица (как требует ТЗ): оценка в %, сортировка по любому столбцу,
  счётчики-фильтры по рекомендации. На телефоне вместо строк — «билеты» с оценкой на корешке.
- Карточка — крупная оценка и шкала «Как сложилась оценка»: все 100 баллов разложены по правилам,
  тёмное — получено, штриховка — недобрано; внизу итог с порогами.
- Фирменная красно-белая гамма B2B-РТС; шрифты Golos Text / Unbounded / JetBrains Mono (Google Fonts). Все цвета — в начале `src/index.css`.
