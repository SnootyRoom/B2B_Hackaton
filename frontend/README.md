# Фронтенд — скоринг закупок (роль 4)

React + Vite + TypeScript, React Router, TanStack Query, Tailwind — как в `CLAUDE.md`.
Экраны и тексты — по разделу «Интерфейс» в `docs/analytics.md`.

## Запуск для разработки

Нужен Node.js 20+ (https://nodejs.org, версия LTS).

```bash
cd frontend
npm install        # один раз, 1–2 минуты
npm run dev        # http://localhost:5173
```

> **Windows, PowerShell пишет «выполнение сценариев отключено»?** Выполните один раз
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` или переключите терминал VS Code на Command Prompt.

По умолчанию включён **демо-режим**: бэкенд не нужен, данные тестовые. Подойдёт любая почта и пароль —
сразу будут три профиля («Основной», «Осторожный», «Агрессивный») и 11 закупок с разными оценками. `new@example.com` — пустой аккаунт,
чтобы пройти путь с нуля: Параметры → «Составить правила» → Загрузка → «Попробовать на примере» → Результаты.

### С настоящим бэкендом

Создайте файл `frontend/.env` со строкой `VITE_USE_MOCK=false`, запустите бэкенд на `:8000`, перезапустите `npm run dev`.
Запросы `/api/...` vite перешлёт на бэкенд. Другой адрес: `BACKEND_URL=http://host:port npm run dev`.

В `docker-compose up --build` фронт собирается с настоящим API и открывается на http://localhost:3000.

## Команды

```bash
npm run dev           # разработка
npm run build         # проверка типов (tsc) + сборка в dist/
npm run lint          # ESLint
npm run format        # Prettier: привести форматирование к общему виду
npm run format:check  # Prettier: только проверить (для PR)
npm test              # Vitest: форматы сумм/дат, проверки правил, разбор реестровых номеров
```

Перед PR: `npm run lint && npm run format:check && npm test && npm run build`.

## Где что лежит

```
src/
  api/
    types.ts        типы данных API (сверить с OpenAPI тимлида)
    index.ts        все адреса API; переключатель демо-режима
    client.ts       fetch с cookie и единым форматом ошибок
    mock.ts         демо-«сервер» (только для разработки без бэкенда)
    mockData.ts     демо-закупки, заказчики, профиль «IT-компания из Томска»
  lib/
    catalog.ts      каталог полей правил, подписи значений, тексты ошибок, субъекты РФ
    rules.ts        формулировка правила человеческим языком, проверки при сохранении
    format.ts       суммы «4 200 000 ₽» / «4,2 млн ₽», даты ДД.ММ.ГГГГ
    regNumbers.ts   разбор списка реестровых номеров (44-ФЗ — 19 цифр, 223-ФЗ — 11, ссылки ЕИС)
    rescore.ts      общая полоска «пересчитываем оценки» под шапкой
    hooks.ts        запросы TanStack Query: пользователь, профиль, опрос задач
  components/       Layout (шапка, вкладки, подвал с картой сайта), Logo (красная кедровая шишка), Breadcrumbs, Ticket, RuleCard, ValueEditor, ProfileList (список профилей и меню), Modal, ui
  pages/            LoginPage, WelcomePage (стартовая), ProfilePage, UploadPage, ResultsPage, ProcurementPage, HistoryPage, ComparePage
```

Новое поле в каталоге роли 3 → одна запись в `FIELDS` (`src/lib/catalog.ts`). Остальное подхватится само.

## Дизайн «сортировочный стол»

- «Результаты» — итог одной фразой и таблица (как требует ТЗ): оценка в %, сортировка по любому столбцу,
  счётчики-фильтры по рекомендации. На телефоне вместо строк — «билеты» с оценкой на корешке.
- Карточка — крупная оценка и шкала «Как сложилась оценка»: все 100 баллов разложены по правилам,
  тёмное — получено, штриховка — недобрано; внизу итог с порогами.
- Фирменная красно-белая гамма B2B-РТС; шрифты Golos Text / Unbounded / JetBrains Mono (Google Fonts). Все цвета — в начале `src/index.css`.

## Несколько профилей и сравнение (задача A)

- **«Параметры»**: слева список профилей (на телефоне — выпадающий список сверху), активный помечен словом «Активный».
  «+ Новый профиль» — пустой, из шаблона «Осторожный» / «Агрессивный» или текстом. У каждого профиля меню «⋯»:
  «Сделать активным», «Дублировать» (копия «… (копия)» сразу открывается на переименование), «Переименовать» (на месте),
  «Удалить» (окно подтверждения; у единственного профиля пункт неактивен). Несохранённые правки — предупреждение при переключении.
- **Шапка**: имя активного профиля на всех экранах, во время пересчёта — значок загрузки; под шапкой полоска
  «Пересчитываем оценки по профилю «…» · 120 из 340» → «Оценки пересчитаны».
- **«Результаты»**: переключатель профиля над таблицей (по умолчанию активный), у строк без актуальной оценки — «пересчитывается».
- **«Сравнение»** (пункт меню): «Профиль A» / «Профиль B», «Поменять местами»; сводка «Стало лучше / хуже / без изменений»
  (она же фильтр), сортировка по разнице, изменившиеся строки подсвечены, «Почему?» раскрывает объяснение от бэкенда, выгрузка CSV.

## Загрузка по реестровому номеру (задача B)

«Загрузка» → вкладка «По номеру»: номера через запятую, пробел или с новой строки (можно столбец из Excel или ссылки
с zakupki.gov.ru), счётчик «распознано N номеров», неверные и повторы видны до отправки. Дальше — прогресс пакета
и статус по каждому номеру: «Ждёт», «Загружаем», «Готово» со ссылкой на карточку, «Ошибка» с причиной и советом;
кнопка «Повторить для ошибок». В «Истории» видно, как загружали — файлами или по номерам.

В демо-режиме номера на `0000` «не находятся в ЕИС», на `9999` — «портал не ответил», на `7777` — «взят из образцов».
«Подставить пример» заполняет поле таким набором.

Какие адреса API вызывает каждый экран — `FRONTEND_API.md`, раздел «Как фронтенд использует контракты A и B».
