# План разработки: 3 дня

Времени три полных дня, поэтому объём урезан до критериев ТЗ. Правило одно: **сначала всё P0 у всех, потом P1, P2 — только если день 3 начался с готовым P0 и P1.** Если функции нет в этом списке — её не делаем.

## Приоритеты

**P0 — без этого не сдаём (критерии ТЗ):**
- Парсинг извещений: адаптеры 44-ФЗ и 223-ФЗ + универсальный адаптер; лот = закупка; коды ошибок; файл с ошибкой не роняет пакет.
- ЕГРЮЛ по ИНН: DaData → кэш → офлайн-профили; `GET /organizations/{inn}`.
- Профиль скоринга: редактор правил в интерфейсе (критерий «без изменения кода»), разбор текста параметров через LLM.
- Движок скоринга по формулам аналитики, правила по умолчанию, стоп-факторы, рекомендация.
- Обоснование по шаблонам со ссылками на правила.
- Эмбеддинги e5 + pgvector для `semantic_match` (ИИ-слой из обязательного стека).
- Celery: пакетная обработка без 504, прогресс.
- Интерфейс: Параметры, Загрузка, Результаты (таблица + сортировка), карточка закупки.
- Авторизация минимальная: регистрация, вход, выход, изоляция по `owner_id`, демо-пользователь.
- `docker-compose up --build`, README с примерами запросов и указанием модели LLM.
- `tests/evaluate.py` и тестовый набор: точность ≥ 80%, время < 10 с.

**P1 — после P0, в этом порядке:**
1. LLM-текст обоснования в фоне (с проверкой чисел).
2. Фильтры и счётчики в таблице результатов, экспорт CSV/JSON.
3. Загрузка zip-архивом.
4. Кнопка «Загрузить пример» (демо-набор).
5. Ручной ввод ИНН в интерфейсе.
6. Несколько профилей скоринга и переключение (в P0 — один профиль на пользователя).

**P2 — не начинать без явного решения тимлида:**
LLM-извлечение в парсере, загрузка по реестровому номеру, `items_coverage`, второй источник ЕГРЮЛ, админка, адаптер ПП 615 (в P0 такие файлы идут через универсальный адаптер).
