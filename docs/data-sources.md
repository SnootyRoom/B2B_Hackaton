# Источники данных и внешние сервисы

Состояние на конец октября 2026 года. Сервисы меняются — при сбое сначала проверьте, что описанное ещё работает.

## ЕИС (zakupki.gov.ru)

**Какие закупки есть в ЕИС.** 44-ФЗ, 223-ФЗ, закупки по ПП РФ № 615 (капитальный ремонт многоквартирных домов) и архив по старому 94-ФЗ. Парсер не должен зависеть от закона.

**Как получить XML отдельной закупки по номеру** (модуль `backend/app/eis/fetch.py`, проверено 13.11.2026). Закон определяется по длине номера:

| Номер | Закон | Запросы |
| --- | --- | --- |
| 19 цифр | 44-ФЗ | один: `https://zakupki.gov.ru/epz/order/notice/printForm/viewXml.html?regNumber=<номер>` |
| 18 цифр | ПП РФ № 615 | тот же адрес, что у 44-ФЗ |
| 11 цифр | 223-ФЗ | два: карточка `.../epz/order/notice/notice223/common-info.html?regNumber=<номер>` — в её HTML найти `purchaseNoticeGuid=<guid>`; затем `.../epz/order/notice/notice223/printForm/viewXml.html?purchaseNoticeGuid=<guid>&purchaseNoticeNumber=<номер>` |

Вручную: карточка закупки → «Документы» → иконка печати. По номеру приходит актуальная редакция извещения — она может быть новее файла в `data/samples/`.

**Ограничения ЕИС и как модуль на них отвечает.**

- **Сертификат.** Сайт подписан сертификатом Минцифры, которого нет в стандартных наборах доверенных: без него httpx падает с ошибкой сертификата. Корневой и промежуточный сертификаты лежат в `backend/app/eis/russian_trusted_ca.pem` (публичные; корневой — https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt) и добавляются к certifi. Промежуточный действует до 19.07.2029, корневой — до 27.02.2032. `verify=False` не используем.
- **Частота.** Не чаще одного запроса в секунду на процесс воркера, таймаут 30 с, свой `User-Agent`. Таймаут, обрыв связи и ответ 5xx повторяются с нарастающей задержкой (2 с, 4 с), затем `EIS_UNAVAILABLE`.
- **Номера нет.** ЕИС отвечает кодом 404 со своей страницей «Страница не найдена» → `EIS_NOT_FOUND`.
- **Зарубежные адреса.** Запросам с зарубежного IP (включённый VPN, зарубежный хостинг) ЕИС отдаёт только страницы из своего кэша, а на остальные адреса, включая существующие номера и поиск, — пустой 404 веб-сервера (146 байт, без страницы ЕИС). Проверено 13.11.2026 через VPN с выходом в Швеции. Это не «не найдено», а `EIS_UNAVAILABLE`: иначе вместо образца из `data/samples/` пользователь увидел бы «закупка не найдена». Сервер и машина для показа должны выходить в интернет с российского адреса, VPN выключен.
- **User-Agent.** 13.11.2026 тот же пустой 404 пришёл и с российского адреса на запрос модуля с заголовком `procurement-scoring/1.0`, хотя запрос с браузерным заголовком в ту же минуту получил XML: ЕИС, похоже, отсекает запросы по `User-Agent`. По решению тимлида модуль отправляет браузерный заголовок `Mozilla/5.0`.
- **Капча и блокировки.** HTML вместо XML, ответы 403 / 429, переадресация → `EIS_UNAVAILABLE` без повторов. Не обходим.
- **Пауза после сбоя.** После `EIS_UNAVAILABLE` модуль 60 с не обращается к ЕИС и сразу отвечает той же ошибкой: большой список номеров не ждёт повторов по каждому номеру, а берётся из `data/samples/`.
- **Доступ.** С российского адреса ЕИС открывается и с машины разработчика, и из Docker (проверено 13.11.2026). На площадке проверить заранее; без доступа загрузка по номеру работает только для номеров из `data/samples/`.

**Массовые выгрузки.** FTP-сервер ЕИС закрыт с 1 января 2025 года. Машиночитаемые данные отдаёт только сервис отдачи информации (SOAP), для него нужен персональный токен из личного кабинета ЕИС, а для токена — электронная подпись. Сервис нестабилен (были ошибки «Токены для сервисов отдачи отсутствуют в ЕИС», адрес менялся с int44.zakupki.gov.ru на int.zakupki.gov.ru). Есть Python-клиент `dars` на PyPI. В первом этапе не используем.

**Лоты.** Единица участия — лот: заявка на конкретный лот, отдельный контракт по каждому лоту, НМЦК на уровне лота. В 44-ФЗ несколько лотов — исключение, в 223-ФЗ зависит от положения заказчика. Позиции внутри лота не делятся: заявка подаётся на весь объект закупки.

## LLM

- **YandexGPT Pro** через OpenAI-совместимый API Yandex AI Studio: базовый URL `https://ai.api.cloud.yandex.net/v1`, эндпоинт `/chat/completions`.
- Для запросов нужны API-ключ (секретная часть) и идентификатор каталога Yandex Cloud. Модель адресуется как `gpt://<каталог>/<модель>`.
- `LLM_MODEL=yandexgpt/latest` — алиас, на конец октября 2026 это YandexGPT Pro 5. Явные модели: `yandexgpt-5.1` (Pro 5.1), `yandexgpt-5-pro` (Pro 5). Актуальный список: https://aistudio.yandex.ru/docs/ru/ai-studio/concepts/generation/models
- Если провайдер не принял `response_format` с JSON-схемой, клиент повторяет запрос с `json_object` и кладёт схему в инструкцию; ответ всё равно проверяется Pydantic.
- Итоговый идентификатор модели обязательно указывается в README.
